# Device Provisioning — v0.3

The standard path: **flash → prep → first boot at HQ → deploy**. Budget
~15 minutes per card hands-off time; batches parallelize trivially.

## 1. Flash + prep (on the Mac)

**One command** (flashes Pi OS Lite arm64, mints an optional per-SD mesh key,
preps the boot partition):

```bash
FLEET_SERVER_URL=https://fleet.example.org \
FLEET_DEVICE_PSK=<the psk> \
WIFI_SSID="VenueNetz" WIFI_PASSWORD="secret" DEVICE_LABEL="OK Linz — left screen" \
  ./deploy/flash_and_prepare_sd.sh disk4
```

Or flash with Raspberry Pi Imager yourself (enable SSH + set the `pi` user in
Imager's settings!) and then run only the prep:

```bash
FLEET_SERVER_URL=... FLEET_DEVICE_PSK=... ./deploy/prepare_sd_card.sh /Volumes/bootfs
```

What prep does:
- copies the fleet client + installer onto the boot partition
- **disables Pi OS auto-expand** (the media partition needs that space)
- writes `fleet-boot-config.json` (server URL, PSK, group, rootfs size)
- optionally writes `fleet-setup.toml` (venue Wi-Fi preseed → zero-touch
  onboarding at the venue; see `deploy/fleet-setup.example.toml`)
- hooks the installer into first boot

## 2. First boot — at HQ, with internet

Insert the card, power the Pi with **Ethernet** (or a Wi-Fi preseed that
works at HQ). The installer needs internet once for packages:

1. installs packages (NetworkManager stack, mpv, PIL/Flask, exfatprogs, Tailscale)
2. carves the **FLEET-MEDIA** partition (rootfs capped at 8 GB, rest = exFAT)
3. installs the fleet services, then reboots into normal operation

Progress: `/var/log/fleet-firstrun.log`. **If it fails (typically no
network), it simply retries on the next boot** — nothing is bricked.

Verify before shipping: screen shows the idle card ("WAITING FOR MEDIA")
with a device ID, and the device appears in the dashboard.

## 3. Deploy at the venue

- **Pre-primed card** (Wi-Fi in `fleet-setup.toml`): plug in, done.
- Otherwise: phone onboarding via the `AEC-PI-XXXX` hotspot
  (see the tech handbook §1).
- No Wi-Fi at all: load media onto the FLEET-MEDIA partition or a USB stick —
  the Pi runs as a standalone kiosk.

## Golden-image cloning (optional, for large batches)

After ONE card has completed first boot, you can clone it (`dd`) to same-size
cards instead of re-running first boot per card. Notes:
- device identity comes from the Pi's SoC serial, so clones do NOT collide;
- machine-id is regenerated by the installer;
- cloning to a **larger** card leaves the extra space unused (FLEET-MEDIA
  keeps the source size) — acceptable, or expand p3 manually;
- per-SD Tailscale authkeys are single-use — clones won't join the mesh
  (irrelevant for meshless/HTTPS deployments).

For AEF26 quantities (~150 Pis), per-card first boot at a HQ bench (USB-
Ethernet dongle, powered hub, a few Pis in parallel) is simpler and fine.

## Legacy paths (removed)

`setup_pi.sh` / `push_to_pi.sh` (SSH push-install with VLC) were removed in
v0.2 — the golden-image path above is the only supported install.
