# Golden-image cloning — provision 150 Pis without installing each one

Instead of flash-and-install every card (which downloads ~200 MB and takes
10–15 min per Pi), you **provision ONE master Pi, capture its card as an
image, and clone that image** to all the others. Clones boot with everything
pre-installed and re-derive their own unique identity — so a clone is *ready*
in ~90 seconds, no internet needed at the venue.

This works because every Pi's identity comes from its **SoC serial**, not the
SD card (designed in from day one), so cloned cards never collide.

## One-time: build the master

1. Flash + provision one Pi normally (`../flash_and_prepare_sd.sh` or
   `../prepare_sd_card.sh`), boot it, let it register in the dashboard.
   Use a **Pi 5** as the master if you can — a Pi 5-built arm64 image runs on
   Pi 3/4/5 alike.
2. Capture it:
   ```
    SSH_OPTS="-i ~/.ssh/your_key -o IdentitiesOnly=yes" \
      ./capture_golden.sh <master-ip> <diskN>
    ```
    This SSHes in, **generalizes** the master (`generalize.sh`: strips
    device-id, machine-id, SSH host keys, onboarding markers and the master's
    Wi-Fi — but KEEPS the installed packages), powers it off, then you move the
    card to the Mac and it images it to `aef-golden-<date>.img.gz`.

## Per card: clone + stamp venue Wi-Fi

```
WIFI_SSID="OK-Linz-Wifi" WIFI_PASSWORD="secret" \
DEVICE_LABEL="OK Linz — Mediendeck left" FLEET_GROUP="ok-linz" \
  ./flash_clone.sh aef-golden-20260708.img.gz disk4
```

Writes the image and drops **this card's** `fleet-setup.toml` on the boot
partition. Put the card in a Pi, power on:

> boots → re-derives its `aef-pi-xxx` identity → joins the stamped Wi-Fi →
> registers in the dashboard. No install, no cable, ~90 s.

You can also drop a filled-in `fleet-setup.toml` with `FLEET_SETUP_FILE=…`, or
skip Wi-Fi entirely (the Pi then opens the `AEC-PI-XXXX` phone-setup hotspot at
the venue).

## What each clone regenerates on first boot

| Unique per Pi | How |
|---|---|
| device-id (`aef-pi-xxx`) | derived from the Pi's SoC serial (`identity.py`) |
| hostname | `fleet-hostname.service` re-derives it |
| machine-id, SSH host keys | regenerated by systemd/ssh on first boot |
| venue Wi-Fi | from the `fleet-setup.toml` you stamped |
| media | pulled from the server per its group, or dropped on FLEET-MEDIA |

## Notes / limits

- Clone onto **same-size or larger** cards. On a larger card the extra space is
  unused (FLEET-MEDIA keeps the master's size) — fine, or grow p3 later.
- The image is a full-card `dd`, gzip-compressed — the empty FLEET-MEDIA space
  compresses well, so the file is far smaller than the card.
- Per-SD Tailscale authkeys (if you use the mesh) are single-use and are NOT
  cloned — irrelevant for the public-HTTPS deployment.
- Re-capture a fresh master whenever the fleet software changes materially.
